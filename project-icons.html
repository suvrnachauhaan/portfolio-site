200 Icons. One System.

Built a scalable icon library — one visual language, infinitely extendable.

Overview

The product had 200+ icons sourced from 4 different libraries, 3 freelancers, and a grab bag of one-off SVGs. No consistent stroke width. No shared grid. No naming convention. Every new feature meant hunting for an icon that "sort of" matched.

I was tasked with building a unified icon system from scratch — one that could scale with the product and be used consistently across web, mobile, and marketing.

Icon Grid — Full Library Overview
The Problem

Inconsistency was everywhere. Some icons were filled, others outlined. Stroke widths ranged from 1px to 2.5px. Corner radii varied. Optical sizing was ignored — a 16px icon scaled to 24px looked muddy; a 24px icon at 16px lost detail.

Developers were spending time tweaking SVGs inline. Designers were redrawing icons per project. There was no single source of truth.

Before — Inconsistent Icon Samples
After — Unified Grid & Style
Process

Audit: Catalogued every icon in the product across platforms. Found 214 unique icons, 47 near-duplicates, and 31 that were used exactly once.

Grid & Rules: Designed a 24×24 grid with 2px padding, 1.5px stroke width, 2px corner radius, and round caps. Every icon follows the same optical weight rules.

Drawing: Redrew all 200+ icons by hand in Figma, following the new spec. Each icon was tested at 16px, 24px, and 32px for clarity.

Delivery: Built a Figma component library with variants (outline/filled), exported optimized SVGs, and wrote usage guidelines for the engineering team.

Reflection

Icons feel small. They're not. They're the visual vocabulary of your product. When they're inconsistent, everything feels slightly off — even if users can't articulate why. Building this system taught me that craft at the atomic level compounds across every screen.
