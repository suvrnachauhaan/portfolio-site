03 Animation · Rive

Motion with Purpose

Used Rive to make animation that earns its place. Not decoration — direction.

Overview

A fintech app wanted to add "delight" to their product. Their first instinct: Lottie confetti on every success state. My counter-proposal: purposeful motion that guides attention, communicates state changes, and reduces cognitive load.

I used Rive to create interactive animations that responded to user input — not just decorative loops, but functional motion that made the interface feel alive and responsive.

Animation Showcase — Key Interactions
The Problem

The app felt static. State changes were jarring — screens swapped with no transition, loading states were generic spinners, and success/error feedback was limited to text banners. Users reported the app felt "cold" despite a warm visual identity.

The team wanted animation but had no framework for when, where, or how much motion was appropriate.

Animation Decision Framework
Process

Audit: Mapped every state change in the app — 34 transitions, 12 loading states, 8 success/error moments. Prioritized the top 15 based on frequency and user impact.

Principles: Defined a motion language: ease-out for entrances (welcoming), ease-in for exits (decisive), spring curves for interactive feedback (alive). Duration rule: nothing over 400ms.

Rive: Built state machines in Rive for the 6 most complex interactions — including a payment confirmation that responds to success/failure with different animations driven by the same state machine.

Handoff: Exported Rive files with clear state machine documentation. Worked with devs to implement runtime control via Rive's web runtime.

Reflection

Motion is a design material, not a garnish. The hardest part wasn't making things move — it was deciding what shouldn't move. Restraint is what separates purposeful animation from visual noise.
